# Ring Pipeline Fixes - October 30, 2025

## Issues Fixed

### 1. **ValueError: too many values to unpack (expected 2)**

**Problem:**
When running ring pipeline inference in single-node mode, after the first chunk of layers processed the input, it would output a 3D tensor (logits with shape `(1, 7, 151936)` - batch, sequence, vocab_size). When this was passed back for the next chunk of layers, the inference code expected a 2D input `(batch_size, seq_len)` and failed with:

```
ValueError: too many values to unpack (expected 2)
```

**Root Cause:**
In `transformers_inference.py`, the `_infer()` function at line 175 checked if the shard was the first layer and then expected 2D input (token IDs). However, in ring pipeline mode, even the "first shard" might receive 3D input (hidden states or logits) when processing continues locally.

**Solution:**
Modified the condition in `transformers_inference.py` line 175 from:

```python
if self.shard.is_first_layer():
```

to:

```python
if self.shard.is_first_layer() and input_tensor.dim() <= 2:
```

This ensures that:
- If we receive 2D input (token IDs), we treat it as the first layer with embeddings
- If we receive 3D input (hidden states/logits), even on the "first shard", we treat it as middle/last shard processing

### 2. **No Ring Re-initialization on Topology Updates**

**Problem:**
When a new node joined the network, the topology would update, but the ring pipeline wouldn't re-initialize to distribute layers across the new topology. The original node would continue processing all layers locally.

**Root Cause:**
The `topology_update` message handler in `main.py` only updated the local topology dictionary but didn't trigger any re-initialization of the ring pipeline.

**Solution:**
Added a new method `on_topology_update()` in `llm_service.py` that:

1. Detects topology changes
2. Logs the change with a clear banner
3. Re-initializes the ring pipeline with the updated topology
4. Displays the new layer distribution across all nodes

Modified `main.py` to call this handler whenever a topology update message is received:

```python
# Re-initialize ring pipeline if LLM service is running in ring mode
if llm_service and llm_service.is_running and llm_service.use_ring:
    asyncio.create_task(llm_service.on_topology_update())
```

## Files Modified

### 1. `transformers_inference.py`
- **Line 175**: Added dimension check to handle both 2D (token IDs) and 3D (hidden states) inputs

### 2. `llm_service.py`
- **Lines 552-581**: Added `on_topology_update()` method to handle ring re-initialization when topology changes

### 3. `main.py`
- **Lines 54-57**: Added automatic ring re-initialization trigger on topology updates
